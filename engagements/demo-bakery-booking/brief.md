# 烘焙工坊共享设备预约

模拟客户及内部测试者。FDE 在原邀请会话确认相邻时段、当天预约和本人取消规则，再采用到规格 v2。原话、消息 ID、Task 与 Run 见[演练证据](../../docs/operations/evidence/onefde-booking-pilot-20261106.json)。

## 设计检查点

- 一台设备，试点当天。同一时段按左闭右开判断。预约冲突由服务端返回，原预约保留。
- 服务端用 SQLite 存预约。用一个写事务处理重试、检查重叠和插入。不同请求并发时，第二笔写入等待前一笔结束后重新检查。
- 模拟店员在独立浏览器会话登录。服务端从会话取身份，取消时核对预约人。网页通过本机 HTTP 接口预约、列表和取消。试点使用合成账号，交付环境的真实认证另定。
- 先运行预约、持久化和刷新，再补并发、重试和取消。独立检查对同一固定归档运行。商家用语和使用流程通过浏览器另验。

接受后先核验回环入口，再由 Business 在原邀请会话发内部试用说明。

## 当前状态

固定归档已在工作台登记接受。已核验的独立回环入口通过原邀请会话通知 14 提供给内部测试者。两位模拟店员复测冲突、越权取消及取消后重新预约，通过反馈 15 回到同一会话。正式发布单独跟踪。

## 店长代取消续办

原邀请会话确认普通店员仍只能取消本人预约，店长可以代取消当天预约并须填写原因。记录保存预约编号、预约人、实际操作人、原因和带时区时间，只有店长可读。重复操作保留原记录。原因按试点规格限制为去除首尾空白后 1 至 120 字。

原接受归档和新增回归已固定为关联 Task 的工程基线。真实工程提交、独立复验和浏览器验证完成。新版本等待工作台评审。 [关联 Task 和证据](../../docs/operations/evidence/onefde-booking-manager-real-20261106.json)
