# Capability Library 与知识服务约定

能力库保存可跨项目复用的行业知识、业务模块和工程经验。每个条目应说明它解决什么问题、何时适用、依赖什么，以及依据哪些实现和样例验证过。

已有黑客松最小资产：[`fresh-quote-compare-csv`](fresh-quote-compare-csv/CAPABILITY.md)（限制使用，内部复用）。另有权限夹具 `fixture-restricted-supplier-notes`（不可列表/读取）。能力库不等于聊天历史、项目原始资料或一组 Agent Skills。

第二项目采用与再检查见 [demo-supplier-quotes-reuse](../engagements/demo-supplier-quotes-reuse/brief.md) 与 [P3 证据](../docs/operations/evidence/p3-reuse-recheck.json)。网页冒烟或模型总结不能自动标为已验证；本条仅为列明样例范围内的限制使用。

## Knowledge、能力库与业务资料

| 对象 | 负责什么 | 不承担什么 |
| --- | --- | --- |
| Knowledge Agent | 同时为 Business、FDE、Engineering 提供检索分析、解释比较和复用支持；接收三者反馈，整理维护候选资产 | 不代行经营决策、确认客户规则、改变 Task 范围、工程验收或授予资料/发布权限 |
| Capability Library | 持久保存知识/模块/经验的身份、版本、来源、条件、实现引用和验证范围，供受控检索读取 | 不主动调用模型、派工或作业务判断；不是一个常驻 Agent |
| 业务资料 | 保存公司经营记录、沟通原文、Engagement、客户证据、方案和交付/反馈事实，归相应业务对象维护 | 不是天然可跨项目复用或公开的知识；不因被咨询引用就自动迁入能力库 |

能力库和业务资料是不同逻辑对象，可共同使用 PostgreSQL、Git 引用和对象存储，不因此新增一种数据库。Knowledge 通过受控工具查询这两类来源；咨询结果是派生建议，既不取代来源事实，也不自动成为能力条目。原产品定义保留归档，当前职责以 PRD 为准。

## 同时支持三个专业角色

| 请求方 | 给 Knowledge 的最小输入 | 应获得的支持 | 由请求方承担的判断 |
| --- | --- | --- | --- |
| Business | 经营问题/材料用途、实际请求或经营记录归属、所需案例/服务能力及受众 | 获准案例与可展示成果、行业知识、能力说明/限制、材料依据；明确哪些是模拟、未验证或仅内部可用 | 市场/销售判断和材料取舍；价格、合同、客户承诺及公开权限回创始人 |
| FDE | 问题/目标、已确认规则、业务数据条件、相关项目授权 | 业务知识和既有方案检索、候选能力比较、适用前提、复用/组合限制及缺口 | 客户业务含义、方案和范围取舍；关键承诺回创始人 |
| Engineering | Task/Run 归属、实现目标、技术/接口约束、已有能力版本和具体问题 | 模块及代码引用、接口/依赖/兼容说明、适配建议、已记录调试/构建/部署经验与检查依据 | 实现选择、实际集成和重新检查；业务规则不清回 FDE |

两种调用路径并存：三个角色的简单查询/读取直接使用受控能力库或业务资料工具；有界解释/筛选/比较调用 Knowledge，访问均经过同样的权限过滤。记录实际调用身份、问题、工作归属、资料用途/受众、输入引用和结果；身份由程序注入，不由模型自称。Business 的公司级咨询可用请求/经营记录关联，不强迫创建客户 Engagement 或虚构 Task/Run；已有 Task/父 Run 时必须保持关联。工程或经营知识咨询不要求 FDE 中转。

需要长时间研究、等待或产出独立可验收资产时按统一任务协议记录关联工作，不无限阻塞父 Agent 或递归互调。当前工程切片接口尚未覆盖公司级或 Knowledge 任务，具体入口在对应实施阶段扩展，不把逻辑能力说明当作已实现 API。

Knowledge 返回获准资产 ID/固定版本或业务来源版本、相关实现/证据、适用条件、限制及可用用途；未验证/未确认与无可用结果如实标注。没有可见权限时不暴露受限资料的正文、标题或链接。答复回实际来源请求/经营记录/Task/Run，采用理由、最终使用版本和后续检查可追溯；建议不等于业务授权、实际测试或新确认事实，不改写正在运行的规格。

## 权限、公开用途与事实边界

- 有效访问由实际调用方、当前工作范围、来源授权与本次用途共同约束。Knowledge 的服务身份或其他项目的 Session 不扩大调用方可见范围；在检索和装配模型上下文前过滤资料，输出及附件/代码下载再次核对。
- 单创始人登录不等于每个 Agent 拥有创始人的全部读取权；角色工具白名单与本次工作授权仍生效。切换项目、请求方或公开用途时重新装配上下文，不直接复用含受限来源的历史 Session；权限撤回后按现行规则过滤或重建上下文，不以旧模型记忆绕过。
- 内部可见、跨项目可复用、可用于客户材料/公开展示是不同权限。已验证也不等于可公开；Business 不因需要写宣传材料而获得客户原始数据、专属代码、内部报价或合同。
- 公开案例采用已明确授权的版本/视图；脱敏草案不能由 Knowledge 自行宣布可公开。引用、摘要和派生建议继承来源限制，不以总结、复制或混合多个来源绕过权限。
- 来源事实区分已确认、待确认、模拟和观察；资产另有验证范围。Knowledge 不将客户猜测升为规则，不将一次实验或冒烟升为稳定交付能力，不以推荐替代 Engineering 的实际检查。
- 发布、商业承诺、关键业务范围及资料公开授权按创始人既有职责执行。FDE 判断客户方案，Engineering 判断实现并提交证据；Knowledge 只提供有依据支持，不接受自己的候选资产为“已验证”。
- 更新/弃用、权限撤回或源版本变化后，新查询核对当前授权与有效性，受影响任务提示重新核查；历史引用保留受控追溯，不通过共享查询回显撤权内容。留存/删除期限仍按真实资料政策确认。

## 分类与条目

| 类型 | 可能沉淀的内容 |
| --- | --- |
| 行业知识 | 商品规格、单位口径、报价可比条件等经确认的规则 |
| 业务模块 | 文件解析、字段映射、价格比较等可引用实现 |
| 工程经验 | 文件兼容、异常处理、构建和部署中验证过的方法 |

有实际候选资产后，可创建 `<capability-id>/CAPABILITY.md`。不预先生成空条目；代码模块、规则或经验也不必全部包装成 Skill。运行时存储与检索实现待工程设计确定。

条目最低应包含以下内容，适用字段可以合并成段落：

- 稳定 ID、名称、资产类型、版本及更新时间。
- 解决的问题、适用场景、前置数据和环境、输入输出。
- 业务规则、依赖与兼容版本、限制、异常和不适用场景。
- 实现或资料引用，固定对应的代码/模块版本。
- 来源 Engagement、资料或任务，以及可追溯的运行和检查依据。
- 验证状态、验证过的样例与范围，尚未验证的部分。
- 复用范围：通用、受限或客户专属，以及范围的确认依据。

## 验证状态

| 状态 | 使用含义 |
| --- | --- |
| 草稿 | 候选内容尚未充分验证，可供研究；用于新交付前重新核对 |
| 已验证 | 在条目列明的场景、版本和样例上有验证依据；不代表任意场景适用 |
| 限制使用 | 已知限制只能在明确条件下使用，调用前核对限制 |
| 已弃用 | 保留历史来源和使用关联，后续检索应说明不再推荐使用的原因及替代项 |

这是条目状态的初步记录约定。条目提升验证状态时必须有明确证据与适用范围；具体检查阈值随资产类型在阶段 B/E 细化。模型生成总结、一次运行返回成功或检索排名靠前，均不足以自动标为已验证。

## 黑客松最小资产与第二项目验收入口

| 检查项 | 最低要求 | 当前 |
| --- | --- | --- |
| 候选资产条目 | 稳定 ID、来源 Engagement/Task、固定实现或资料版本、适用条件、权限、验证状态 | `fresh-quote-compare-csv@1.1.0`（限制使用） |
| 三角色咨询 | Business/FDE/Engineering 可按权限直接查询或请求 Knowledge；身份由程序注入 | `POST /api/v1/knowledge/tools`（无模型循环） |
| 第二项目采用 | 记录选用版本、适配改动与重新检查；不是粘贴上轮聊天 | `demo-supplier-quotes-reuse` + 再检查证据 |
| 权限反例 | 无授权看不到受限正文/标题/链接（HM07） | 夹具 + 集成测试通过 |

## 复用流程

FDE 根据目标与输入检索能力，并核对业务语义、版本、依赖、限制和复用权限，再选择直接复用、组合扩展或局部开发。任务记录候选与采用理由，执行结果记录实际使用版本、适配和重新检查。

Business 可检索获准行业知识、服务能力与交付案例，必要时请求 Knowledge 整理材料依据；经营原文、市场假设和营销稿仍保留在业务记录中。只有明确具有复用价值且来源/权限清楚的提炼内容才成为候选资产，不为支持经营新建一套泛化文档仓库。

Engineering 在任务范围内可再次检索或咨询 Knowledge，核对具体模块的接口、依赖、实现和兼容证据，选择如何集成并执行检查；不把 FDE 已选资产理解为“无需再分析或测试”。若候选改变已确认业务规则或工程范围，提交原 Task 由 FDE 处理，不能以 Knowledge 的建议自行扩大授权。

直接复用仍需要配置、运行与结果检查。组合模块必须检查接口和规则兼容性；单模块通过不代表组合交付正确。资料不足或适用条件无法确认时，FDE 先澄清，不能由 Engineering 凭猜测扩大能力适用范围。

## 来源与维护

Business 回传市场/销售反馈与材料修订依据，FDE 回传业务条件、方案取舍及使用反馈，Engineering 回传实现版本、接口/兼容变化和检查证据。Knowledge 先核对来源、事实状态、权限与复用价值，再提炼为候选条目/修订，通过受控维护操作入库；完整原文仍归业务记录。状态提升需明确证据，不能仅凭咨询答复或执行结束自动提升。客户数据、专属实现、商业信息与凭据留在原有范围；创始人确认可跨项目复用与对外展示范围，必要时只保留授权视图或脱敏引用。

来源、授权或复用范围不清的内容先保留在原 [Engagement](../engagements/README.md)，不进入通用资产。更新能力时保留历史使用版本与变更说明，避免既有项目的实现含义随条目改写。
