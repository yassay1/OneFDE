# Frontend design

OneFDE adaptation of anthropics/skills. Modified for business tools, existing design systems and scoped Engineering delivery. See bundled provenance and Apache-2.0 license.

Identify the user, the primary operation and the information needed to complete it. Use the confirmed brief and existing product conventions. For a utility, lead with the working input and result; choose a landing-page composition only when that serves the brief.

Choose a coherent visual direction grounded in the business: type scale, spacing, colors and grouping. Build clear hierarchy around real content. Follow an existing design system when present; avoid adding libraries, fonts or external media without a concrete need and permitted access.

Make primary and secondary actions distinct. Provide readable labels, keyboard focus, understandable errors, empty/loading states and honest sample-data labels. Keep long tables usable on narrow screens without forcing the entire page to overflow. Preserve the user's entered data during unrelated filtering and navigation where appropriate.

Implement a working path before optional decoration. Check the actual page when browser tooling is available, with attention to contrast, clipping, text wrapping and control placement. Describe unverified visual behavior explicitly. Use task criteria and the registered checks to decide completion.
